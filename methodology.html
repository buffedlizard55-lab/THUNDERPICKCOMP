Core values — our decision filter

Maximize P(Win) — “Maximize the Probability of Winning”: in every tradeoff we pick the path that maximizes this project's chance of becoming a genuinely useful, trustworthy daily hub. We set aside emotion and put the project first.

Own the Outcome — we own results end to end, not just our slice. When we can act, we do — without waiting for permission. Failures and successes are signals to improve. At every turn we stay accountable to the final outcome.

These are the focal point when building, researching, suggesting upgrades, and implementing work — per the README charter. The mission is to solve the manual-checking problem: a current, traceable daily feed so users don't have to manually track HLTV, Liquipedia, team feeds and markets.

Verification rules (non-negotiable)

  1. No hallucinations. Teams, rosters, odds, prices, results, stats, dates — if it can't be checked against a source, it's unknown/TBD.
  2. Claim by claim. Every material statement links to the source it was checked against, with a retrieval timestamp. A search snippet is not verification.
  3. Primary sources first: organizer releases, teams/players, Valve, exchange APIs — then HLTV/Liquipedia structured records, then reputable press with attribution.
  4. Fact vs analysis. Verified facts, calculations, model heuristics and simulated outputs are labeled as such. Strategy theses are testable rules, not punditry.
  5. Free public sources only. No paid API or subscription. Source terms, rate limits and attribution requirements are respected.
  6. Fail visibly. Missing feeds, stale prices and conflicts are shown as flags — never smoothed over.

Settlement, source scope & reproducibility

  • What is automatically collected: Valve's latest published Global VRS file (ranked rosters, not live event starters); a conservative Liquipedia fixture/result template parse (explicit UTC date+time and a whitelisted timezone only); a bounded HLTV match-page cross-check (same HLTV id must name the same two teams and UTC date before a fixture is scheduled-confirmed; results need HLTV's series score and Liquipedia's map scores to agree); bounded Polymarket event searches (Thunderpick-keyed plus per-finalist team searches) and outcome-specific CLOB best asks; bounded Kalshi CS2 game/outright series and first-party Yes asks. Each query's scope, timestamp and failure are published on Markets.
  • What is simulated: the FURIA/Falcons outright policy and the six match strategies are active with gates: a match decision requires a double-sourced fixture (HLTV + Liquipedia agree on HLTV id, teams and UTC date), a strictly pre-start, same-run, fresh first-party ask whose top-of-book size covers the stake, and an unambiguous quote-to-fixture association. The group draw is TBD, so nothing can be papered yet; no opponent, result or price is ever invented. The control account never bets.
  • Gross math: a $1-winning share at ask p has modeled decimal factor 1/p; on confirmed win the gross paper payout is stake/p rounded to cents. Real fees, slippage, order size and tax are not modeled. Settled P/L is payout − stake; pending stakes are locked, with no realized ROI.
  • Settlement journal (append-only, hash-chained): every pending position gets venue-resolution receipts (Kalshi status/result/settlement-value; Polymarket UMA status/outcome prices) recorded verbatim, plus independent result confirmation (the double-sourced fixture journal for matches; Liquipedia's infobox winner and a confirmed playoff result for the outright). The ledger changes only on a settlement_decision receipt where venue and independent evidence agree; conflicts stay pending and are flagged. A venue 50/50 settles as partial at the venue's payout fraction — never as a refund. Void is never assumed: a canceled or unresolved market stays pending until the venue itself says otherwise. Every receipt is SHA-256-chained, so edits or deletions of history fail validation.
  • scripts/validate.py checks schemas, provenance, references, duplicate IDs, gross math and the settlement hash chain. Offline unit tests use explicitly partial captured source excerpts and synthetic decision cases that never enter published data.

Durability — versioned archive & stall alerting

The rolling quote/decision/settlement journal lives in Pages JSON, restored each run over HTTPS and from the last successful Actions checkpoint (a 30-day artifact). To survive beyond artifact expiry, every successful publication run now also commits the full journal + a SHA-256 MANIFEST to the journal-archive git branch — one commit per run, versioned by git history, tamper-evident by digest. The latest manifest is published below and re-verified on load. A separate watchdog workflow runs hourly and fails loudly (red run + watcher notification) when the last successful collection is >100 minutes old or the published journal's own last_attempt_utc is >130 minutes old; the site additionally flags the feed stale after 2 hours.

Historical backtesting methodology NEW — SIMULATED

Backtesting answers: what if our 8 simulated strategies had bet the last 90 days of verified matches involving TWC 2026 finalists? We store everything on site for future analysis and strategy building.

  1. Verified match results (no hallucinations): data/historical_matches.json contains 22 matches from Jun–Sep 2026 (FISSURE Playground 3, StarSeries Fall, IEM Cologne Major, TWC Closed Qualifier, XSE Pro League). Each has date, teams, winner, score, map scores where available, verified_utc, and direct HLTV/Liquipedia source URLs for manual review. E.g., HIST-001 Legacy 3-0 G2 Grand Final Sep 13 (HLTV 45509 ↗), HIST-002 Vitality 3-1 Aurora Sep 20 (HLTV 45558 ↗), HIST-009 K27 2-1 VP Sep 9 (HLTV 2397857 ↗).
  2. Real market receipts where free: data/historical_odds.json records Polymarket Gamma closed event 1000135 (3DMAX vs 100 Thieves, TWC Closed Qualifier Group C) — its 0/1 resolution prices are settlement values, NOT pre-match odds, so never used as executable asks. Kalshi open-event discovery (KXCS2GAME/KXCS2, first 200 events, 3 pages max) found 0 TWC 2026 Finals markets as of Sep 24 (see observations.json checks). No free, terms-compliant sportsbook historical odds API has been verified — that is a coverage gap, not proof none exists.
  3. Modeled odds with audit trail: Where no real free line exists, we compute fair_fav = min(85%, 50% + 2.5% * VRS_rank_gap) from ML-008 Sep 16 VRS ranks (Legacy #3, Falcons #4, FURIA #8, BETBOOM #9, 9z #10, Aurora #12, PARIVISION #17, VP #30). Add deterministic noise in [-0.08,+0.08] based on SHA256(match_id) to simulate market inefficiency, then apply 4% overround: market_prob = fair_noisy * 1.04, decimal = 1/market_prob. Formula, noise source, and VRS ranks are published in historical_odds.json modeled_policy and in every backtest ledger entry (odds_detail, fair_probs, market_implied). Labeled MODELED — never presented as a real betting line.
  4. Simulated ledger: scripts/backtest.py loads historical_matches + strategies + VRS ranks, sorts matches chronologically, and for each strategy applies its rule: Favorite Backer picks lower VRS rank (25u), Underdog Hunter picks higher rank (15u), VRS Value bets when market implied < fair_orig - 0.08 (20u), Cache Chaos backs underdogs in group-stage (12u), Qualifier Fade fades VP (20u), Contrarian Cap backs dogs at >=3.00 (10u). Win = stake*(odds-1), loss = -stake, rounded to cents. Control flat_observer never bets. Every bet gets entry_id BT-{match_id}-{username}, date, teams, pick, decimal_odds, stake, profit, result, odds_type=MODELED, odds_detail, reason, and result source links.
  5. Leaderboard analytics: data/backtest_results.json aggregates per-strategy total_bets, wins, losses, win_rate, staked, profit, ROI = profit/staked*100, bankroll = 1000+profit. Sorted by bankroll descending. Analytics includes total_matches, inter_finalist_matches, date_range, VRS ranks, odds policy. Stored on site for future strategy building — e.g., Favorite Backer 22 bets 19W-3L +22.9% ROI in this window; Underdog Hunter -47% ROI; Qualifier Fade -22.8% (VP 5-1 after opener shows rested qualifier seed undervalued).
  6. Future upgrade: When Finals markets open on Kalshi/Polymarket, collect.py will capture first-party best asks with size + timestamps. Backtest can then prefer VERIFIED odds over MODELED where available, with a flag in ledger, enabling real verified betting lines backtesting as requested.

All backtest files are static JSON, versioned in git, published on GitHub Pages. No paid API, no paywall bypass, no ToS violation. Missing data = unknown/TBD, never guessed. See Backtest page → for full ledger.

Player-stat window policy (ratings prerequisite)

Before any player rating is published, the rule is fixed in data/player_stats.json: source = HLTV statistics pages, metric = Rating 3.0, window = trailing 90 days ending at retrieval, minimum 40 maps in-window (below that a value is unavailable, never interpolated), every row carries its exact window dates, source URL and retrieval UTC, and HLTV's robots.txt restrictions on filtered stats URLs are respected. Ratings are analysis inputs, not facts, and must never be presented as proof a market price is wrong. The file ships empty: no compliant collection has run yet.
